# Project P&L для Битрикс24

Встраиваемое веб-приложение для совместного ручного учёта экономики проектов. Показывает доходы, расходы, прибыль и рентабельность каждого проекта и компании в целом.

## Что реализовано

- проекты и назначение нескольких сотрудников;
- доходные и расходные операции с датой, статьёй, комментарием и автором;
- обязательные статьи: внешние программисты, внутренние программисты, расходы на ИИ, аренда сервера, дивиденды;
- пользовательские статьи доходов и расходов;
- автоматический расчёт прибыли и рентабельности;
- общий дашборд и детальный журнал проекта;
- безопасное удаление ошибочной операции;
- общая D1/SQLite-база для одновременной работы сотрудников;
- синхронизация активных пользователей и текущего пользователя через REST API Битрикс24;
- демо-режим без портала и кнопка загрузки показательных данных;
- адаптивный интерфейс для iframe, ноутбука и мобильного экрана.

## Финансовые расчёты

Все суммы хранятся целым числом копеек. Это исключает накопление ошибок двоичной арифметики.

- `Доходы = сумма доходных операций`
- `Расходы = сумма расходных операций`
- `Прибыль = Доходы − Расходы`
- `Рентабельность = Прибыль / Доходы × 100%`
- при нулевом доходе рентабельность отображается как `—`, а не как `0%` или бесконечность.

## Локальный запуск

Требуется Node.js 22.13 или новее.

```bash
npm ci
npm run dev:setup
```

Откройте `http://localhost:5173`. Команда `dev:setup` применит миграции к локальной базе и запустит приложение. Для повторного запуска достаточно `npm run dev`.

Проверки:

```bash
npm test
npm run lint
```

## Развёртывание

Проект рассчитан на Cloudflare Workers + D1 (есть бесплатные лимиты):

1. Создайте D1-базу `project-finance`.
2. Замените `database_id` в `wrangler.toml` на ID созданной базы.
3. Выполните `npx wrangler d1 migrations apply project-finance --remote`.
4. Выполните `npm run build` и `npx wrangler deploy` либо подключите GitHub-репозиторий к Cloudflare.

Никаких секретов в репозитории хранить не нужно.

## Подключение в Битрикс24

1. В Битрикс24 откройте **Разработчикам → Другое → Локальное приложение**.
2. Выберите серверное приложение и укажите HTTPS-адрес развёрнутого приложения как обработчик.
3. Разрешите scope `user` для чтения сотрудников.
4. Откройте приложение из меню Битрикс24. JS SDK передаст временный токен, сервер проверит его запросом к вашему порталу и синхронизирует активных сотрудников.

Адрес портала проходит allowlist-проверку (`*.bitrix24.ru`, `.com`, `.by`, `.kz`), поэтому токен не может быть отправлен на произвольный домен. Токен используется только для текущей синхронизации и не сохраняется.

## Как проверялся результат ИИ

- расчёты вынесены в чистые функции и покрыты тестами, включая копейки, убыток и нулевой доход;
- входные данные проверяются на сервере, суммы принимаются только положительными и не более чем с двумя знаками после запятой;
- внешние ключи и уникальные индексы защищают связи проектов, сотрудников и статей;
- запросы к базе используют индексы по проекту и дате;
- итоговая production-сборка запускается командой `npm test` до передачи результата.
